# Permissions audit (moxy#496)

Design and data only. No permission, tier or profile is changed here; every
default is the operator's call. This page proposes.

**Labels.** *Verified* means read from the parsed tool TOML (the table is
generated by `moxy perms-matrix`, regenerated with `just debug-perms-matrix`
into [permissions-matrix.md](../permissions-matrix.md)) or from a test that
ran. *Inferred* means read from names, descriptions or other repos' docs and
not run.

## What the matrix covers

Verified: every tool of the 17 moxins under `moxins/` (98 tools at 66b98f4):
its tier, who judges its inputs (`broker+floor`, `floor`, `none`, `prompt`,
`client`), its `[resources]` stanzas (input, op, `split` or `grammar`), its
async eligibility, and its annotation hints.

Not covered, and why:

- **Meta tools** (`status`, `restart`, `batch`, `async*`) are Go builtins; the
  `serve-http --expose` categories (FDR 0006) gate them, nothing else does.
- **Children that are not moxins** (chrest, nebulous, smith, stats-me,
  issue-filer and the like): they come from a moxyfile, not from this repo,
  so the repo's sources cannot list them. Inferred: they are always-allow or
  client-delegated as the moxyfile says.
- **Profiles.** The profile lists (spinclass FDR 0034, the in-unit moxyfile
  ceiling, circus EPIC 0001 role profiles) live in other repos and I did not
  read them; the matrix has no profile column. Verified in this repo: the
  exposure levers are `serve-http --expose` (categories only, FDR 0006) and the
  moxyfile's `allow-tools` / `pass-tools` (tool-level, narrowing, FDR 0013).

## Ungated path readers today

Verified: always-allow, no `[resources]` stanza. Inferred: "path reader" is a
name match on the inputs (`path`, `*_dir`, `repo_path`, `session_id`, `name`,
`page`, ...). The list is pinned in `zz-tests_bats/perms_matrix.bats`, so a new
one fails a lane until someone decides it.

| tool | status | smallest change |
|---|---|---|
| `env.resolve` | verified: reaches `/proc/self/{cwd,exe,fd/*,root}` (moxy#497) | `[resources.path] op=read` + folio-perms floor; refuse `/proc`, `/sys`, `/dev` on the resolved result, not the argument; `--` before the path. On hold until the operator decides. |
| `env.get` | verified: with no name it lists every variable (~230 in this process) | drop the no-name listing; allowlist names (operator decides the list). |
| `env.which` | verified: tells whether any path exists | refuse a name with `/` or a leading `-`. |
| `folio.df` | verified: no stanza | `[resources.path] op=read` + `[dynamic-perms] folio-perms read`, as `folio.du`. Reads filesystem metadata only. |
| `chix.log`, `derivation-show`, `store-cat`, `store-ls`, `store-path-info`, `store-realize` | verified (moxy#495 bats): inputs must be store paths, `.`/`.#attr`, registry names or `github:`/`gitlab:`/`sourcehut:` refs, else exit 2 | none for the file read: the guard is the gate. Decide whether a guard counts as "decided"; if so, mark these in the pinned list as such. |
| `chix.build`, `run`, `flake-check`, `flake-lock`, `flake-update`, `flake-init` | verified: `flake_dir` / `installable` unconstrained; `build` and `run` execute a build | `[resources.flake_dir]` with `read` for check, `write` for init/lock/update, `exec` for build/run; or move `build`/`run` off always-allow. Operator's call: these run code. |
| `freud.*` with `session_id` | verified (moxy#495): id is a UUID or `agent-*`, contained in the projects dir | residual is not a path hole, it is exposure: any unconfined worker reads other sessions' transcripts. Fix is by profile (exclude or scope), not by a stanza. |
| `man.section`, `man.toc` | verified (moxy#495): name is a page name | none; reads whatever MANPATH holds. |
| `grit.commit`, `grit.merge` | verified: always-allow with `repo_path`, while the other grit tools are `floor` | give them a floor like their siblings, or leave them: grit is leaving moxy (#482). |

The matrix flags what the name heuristic finds; it does not prove the rest are
safe. Tools it does not flag but the operator may want to look at (verified
tier, inferred risk): `piers.tab` is always-allow with `destructive=true`;
`piers.comment`, `piers.batch-update`, `gws.api` (raw API passthrough),
`gmail.*`, `car.*`, `calendar.agenda` and `prison.get` are always-allow and
`open-world=true`; `chix.develop-run` and `chix.store-gc` are
`delegate-to-client`.

## What toolbox (66b98f4) makes redundant

Verified: toolbox's round-one applets are `wc`, `sha256sum`, `b2sum`, `digest`,
`tr`, `sort` and similar (FDR 0016); none replaces `rg.search`, `jq.jq` or a
folio reader yet. Candidates, not redundancies: `rg.search` and `jq.jq` (moxy#502
surveys it), whose reads are already `broker+floor`, so folding them in would
not change what is gated, only where the stanza lives. `folio.df` is not a
candidate: it opens no file. Applet-level rows (`toolbox.run/rg`) are not in
the generated table, because an applet's op is not in the TOML.

## Grit is leaving moxy (#482)

Nine of the 98 rows are `grit.*`; the matrix keeps them until the move, and
the pinned list names `grit.commit` and `grit.merge`. When grit goes, those
rows and two names in `perms_matrix.bats` go with it.

## Not done, and next

- **The profile cross-check** (ask 3: fail when a tool is in no profile
  decision, or a profile names a tool that is gone). It needs the profile lists
  as data. Proposal: each profile owner exposes its tool names as a file the
  moxy lane can read, and `moxy perms-matrix` gains a `--json` form to diff
  against. That is spinclass/circus's lane to decide; I did not read those repos.
- **A gate check on the checked-in table.** `docs/permissions-matrix.md` is
  generated but nothing fails when it drifts; the bats lane pins the ungated
  list only (the bats source set holds `zz-tests_bats/` alone). A flake check
  with the moxins and the doc in its fileset would close it.
- **`go.nix` drift.** `just build-go` rewrites `go.nix` (`golang.org/x/sys`
  v0.44.0 → v0.49.0) on master at 66b98f4. I reverted it and did not commit it:
  it looks like a toolbox dependency that `go.nix` was never updated for, and
  the rule is no lock changes. Someone should land it deliberately.
